# guards.yml 保存警告の修正計画と進捗

作成日: 2026-09-20

## 現象と原因

ゲーム内で「guards.yml の保存状態を確認できません。変更は保留されています。」が繰り返し表示される。`GuardStorage.saveWithResult()` は version 6 を出力する一方、`SafeYamlFile.validateVersion()` は guards の上限を 5 としていた。保存用の一時ファイルを再読込する際に形式検証に失敗するため、正常な保存操作でも警告になる。サーバーログの個別例外は未提供なので、他の書込障害が併存する可能性は残る。

## 作業計画と実施状況

| 段階 | 内容 | 状況 |
|---|---|---|
| 1 | 警告文の発生箇所、読み書きの形式番号、保存経路を確認 | 完了。ソースで不一致を確認 |
| 2 | guards、players、operations の形式番号を共通定義へ集約 | 完了。`StorageSchema` を追加 |
| 3 | 共通保存処理の検証を共通定義へ合わせる | 完了。guards 形式6を許容 |
| 4 | 将来形式を破損と取り違えてバックアップで置換しないようにする | 完了。未対応形式は元ファイルを保護して起動停止 |
| 5 | ビルドと実機での保存・再起動確認 | 未実施。利用者の指示に従い開発担当はテストしない |

## 変更範囲

- `StorageSchema`: 形式番号の単一の参照元。
- `GuardStorage`、`PlayerDataStorage`、`OperationLedgerStorage`: 共通定義を使用。
- `SafeYamlFile`: 保存前の検証に共通定義を使用し、未対応の新しい形式ではバックアップ復旧を行わない。

## 利用者による手動確認

1. サーバーを停止し、`plugins/BodyGuard/guards.yml` と、存在すれば `guards.yml.bak` をコピーして別の場所へ保管する。`players.yml` と `operations.yml` も同様に保管する。
2. 更新後のプラグインを導入してサーバーを起動する。起動直後のコンソールに保存エラーがないことを確認する。
3. 護衛を1体追加するか、既存護衛の名前・モードを変更する。ゲーム内に上記警告が出ないことを確認する。
4. サーバーを停止し、`plugins/BodyGuard/guards.yml` の `version: 6` と変更内容を確認する。
5. サーバーを再起動し、変更した護衛が残っていることを確認する。
6. 警告が続く場合は、サーバーコンソールに出る `guards.yml の保存に失敗しました` の直後の例外全文を取得する。権限不足やディスク障害など、別原因の切り分けに使う。

## 引き継ぎ事項

今回の作業は画像の保存警告に直結する形式番号の不一致と、隣接する将来形式の誤復旧に限定する。`docs/OVERHAUL_SPEC.md` にある他の改善項目は未実装。ビルドと実機結果は未確認であり、確認後にこの文書へ日時と結果を追記する。
