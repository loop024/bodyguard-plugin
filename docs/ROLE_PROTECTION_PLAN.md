# 役職保護 実装計画・進行記録

## 目的

`ROLE_PROTECTION_DESIGN.md` を唯一の仕様基準として、既存の所有者向け護衛を壊さず、役職プレイヤーの保護と追従・警備でのワールド間移動を実装する。作業環境は Windows 10、Spigot 1.21.8、Java 21。ビルドは既存 `build.bat` / Maven を利用する。

## 作業順と完了条件

1. **仕様固定**: `役職 = 権限ノード`、複数候補の選択規則、待機モードのワールド間挙動を本設計書に合わせる。既存仕様との矛盾があれば先に設計書へ記録する。
2. **データと設定**: `GuardData`、`GuardStorage`、PDCキー、`config.yml` の検証と旧データ移行を追加。旧 `guards.yml` が OWNER 扱いで読め、保存失敗時に変更を戻せる状態で完了。
3. **対象選択**: 役職権限を持つオンライン候補を決定的に選ぶ処理を `GuardManager` に集約。権限喪失・死亡・ログアウトで解除できれば完了。
4. **移動と戦闘**: 既存の低頻度タスクに追従と移動警備を追加。別ワールドで安全地点が見つからない場合は保留し、対象・所有者・友人を攻撃しなければ完了。
5. **操作画面**: コマンド、補完、GUI、通知、診断へ設定と保留理由を追加。未読み込み護衛への操作は既存の方針どおり安全に失敗・保留表示とする。
6. **文書更新**: READMEに役職権限の付け方、3モードの違い、設定例、ワールド間移動の制限を記載する。
7. **利用者による確認**: 下記の手順を利用者へ渡す。AGENTS.md の指示に従い、開発担当はテストを実行しない。確認結果を受けて不具合を修正する。

## 先に注意する実装上の落とし穴

- 現在の `commandGuardsToTarget` は所有者の全護衛を対象とする。役職保護では護衛単位に変更しないと別の役職担当まで動く。
- 現在の `GUARD` は固定地点警備。役職保護の時だけ対象周辺の移動警備にし、既存 OWNER 護衛の地点を上書きしない。
- `GuardTask` は既に追従の別ワールド移動を扱うが、未読み込み Entity は移せない。保存座標だけ先に書き換えると護衛を見失うため禁止。
- PvP、飛び道具、爆発などは経路が異なる。`CombatListener` と `isForbiddenTarget` の両方を同じ保護判定へ統一する。
- `PlayerChangedWorldEvent` の位置確定前に移動しない。次のタスクで最新の対象UUIDとワールドUUIDを確認する。

## 実装済みの主な経路

- `GuardData` に `OWNER` / `ROLE`、役職ID、最終選択UUID、選択リビジョン、保護状態、保留理由を追加。
- `GuardStorage` の形式を6へ更新し、既存記録をOWNERとして読み込み、型・UUID・役職ID・状態を検証。不正レコードは既存の `quarantine.yml` 経路へ送る。
- `BodyGuard` で `role-protection` を検証し、権限ノードと優先順位を読み込む。優先順位は候補選択ではなく表示順だけに使用する。
- `GuardManager` に決定的な役職候補選択、選択UUIDの保存、設定変更の保存失敗ロールバック、護衛単位の役職対象指令、PDC整合性確認を追加。
- 既存の10 tick共通 `GuardTask` で追従・待機・対象周辺警備を処理し、別ワールド移動は安全地点への成功時だけ位置を更新。安全地点不足・設定無効・未読み込みは保留する。
- `CombatListener` と `isForbiddenTarget` で、選択中対象・所有者・仲間・同一所有者の護衛への誤射を防止し、役職護衛への指令を選択UUIDで絞る。
- `PlayerListener` はワールド変更、リスポーン、死亡、観戦切替、ログイン・ログアウトで再評価要求だけを立て、移動は次の共通タスクで行う。
- `/bg protect`、タブ補完、詳細GUI、通知、READMEを追加。GUIの役職警備は「保護対象の周囲を中心に移動警備」と表示する。

## 引き継ぎ時点の残作業

- 開発担当はMaven、ビルド、テスト、Spigotサーバー起動を実行していない。ユーザーがJarを作成して、下記の手動確認を行う。
- 不具合が出た場合は、実行コマンド、護衛UUID、対象UUID、両者のワールドUUID、`/bg protect status` の表示、コンソールの抑制ログ全文を記録する。
- 役職設定を変更する場合は、設定を保存してから `/bg reload` を実行し、未定義役職の護衛がOWNERへ勝手に変わらず停止することを確認する。

## 初心者向けの手動確認手順（実装後）

サーバーを停止して `plugins/BodyGuard` フォルダーを丸ごとコピーし、実装後の Jar に入れ替えて起動する。権限プラグインでテスト役のプレイヤーに `bodyguard.role.king` を付ける。所有者Aが護衛を1体作り、`/bg protect king` を設定する。結果を `/bg protect status` と護衛詳細画面で確認する。

1. **追従**: Aとは別のプレイヤーBに king 権限を付け、Bが歩くと護衛が付いてくるか見る。Bが別ワールドへ移り、護衛が安全な場所へ現れるか確認する。
2. **警備**: 護衛を警備へ切り替え、Bの近くの敵へ反応し、遠くまで追いかけず戻るか見る。Bが別ワールドへ移ったら護衛も移るか見る。
3. **待機**: 待機中にBが別ワールドへ移っても護衛は元の地点に残るか見る。
4. **対象変更**: Bの king 権限を外す、ログアウトする、死亡する各場面で護衛が無関係な人を攻撃・追従しないか見る。別の king 権限保持者Cがいる場合、適格なCへ切り替わるか見る。
5. **誤射**: 護衛の攻撃や矢がA、B、フレンド、自分の他の護衛を傷つけないか見る。PvP設定に従い敵プレイヤーへの反応も見る。
6. **保存**: サーバーを停止・再起動し、同じ護衛UUID、役職設定、モードが残るか見る。古い護衛も従来どおり OWNER 対象か見る。
7. **失敗時**: `teleport.different-world: false` にして移動しない理由が表示されるか見る。対象ワールドを一時的に利用不能にした場合、護衛が消えたり増えたりしないか確認する。コンソールにスタックトレースが出たら、その全文と操作手順を保存する。

各項目で期待と違う動きがあれば、実行したコマンド、対象と護衛のワールド名、`/bg status` の表示、コンソールの該当ログを記録する。
