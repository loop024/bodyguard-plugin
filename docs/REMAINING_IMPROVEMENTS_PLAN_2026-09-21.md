## 実装方針

1. `config.yml` と `messages.yml` の候補を一度だけ読んで検証する。成功時に両候補を反映し、失敗時は現在値を保持する。
2. 一括呼び戻しは移動数を維持し、保存失敗を結果に含める。コマンドとGUIの両表示を確認する。
3. 設定可能な護衛処理上限と継続位置を導入する。例外がある護衛でも次の護衛へ進む。
4. `players.yml` の形式を更新し、個人設定を追加する。既存の案内、相棒、仲間のデータを保持する。設定保存成功後にだけ表示を切り替える。
5. コード差分を静的に確認し、利用者用の手動確認手順を記録する。

進捗: 1〜5をコード上で実施。呼出し元、GUI画面種別の分岐、保存形式番号と表示キーの参照を静的に確認した。ビルドと実機確認は未実施。

## 調査で確認した点

- `BodyGuard.reloadSettings()` は設定を検証した後に再読込し、messagesも再読込するため、検証したデータそのものを反映していない。
- `GuardManager.teleportGuards()` は移動後に保存が失敗すると移動数を0へ戻す。
- `GuardTask.run()` は毎周期すべての護衛を巡回する。
- 司令メニューの個人設定枠は準備中であり、`players.yml` には個人設定がない。

## 実装記録

- 設定: `BodyGuard.getConfig()` が検証済みの設定候補を返すようにし、`MessageUtil` も同時に読み込んだ候補を採用する。どちらかを読み込めない場合は現在値のままにする。
- 呼び戻し: `RecallResult(moved, saved)` を導入。移動後の保存失敗でも移動数を0へ変更しない。コマンド、司令メニュー、一覧画面に保存未確認を表示する。
- 巡回: `performance.max-guards-per-cycle` を追加。稼働中の護衛を継続位置から最大100体ずつ処理する。保存、チャンク管理、整合処理の処理量は今回の設定対象ではない。
- 個人設定: `players.yml` の対応形式を4に更新。旧形式の案内、仲間、相棒を読み込みつつ、通知、GUI音、照準表示、初期順を保存する。旧ファイルに項目がない場合は既定値を使う。設定保存が失敗したら表示とメモリ値を元に戻す。
- 新しい設定の表示文言は既存 `messages.yml` の日本語フォールバックを持つ。

## 利用者による手動確認

サーバー停止中に `plugins/BodyGuard/config.yml`、`messages.yml`、`players.yml`、`guards.yml` を別の場所へコピーする。新しいJarに入れ替えて起動した後、次を順番に確認する。

1. **再読込**: `config.yml` の `follow.start-distance` を有効な値に変更し、`messages.yml` の任意の案内文を変更する。`/bg reload` 後に両方が反映されることを確認する。次に `messages.yml` に構文エラーを一時的に入れて `/bg reload` を実行し、変更前の設定とメッセージが維持されることを確認する。ファイルを戻して再読込する。
2. **呼び戻し**: 護衛を離れた安全な場所へ置き、`/bg tp` と司令メニューの「全員集合」、一覧の「全員集合」をそれぞれ使う。移動数が実際の体数と合うことを確認する。保存失敗の表示は通常の環境では再現不要。実際に発生した場合は移動数が0に偽装されず、保存未確認の案内が出ることを確認する。
3. **巡回**: 可能なら2人の所有者で合計11体以上の護衛を用意し、`config.yml` の `performance.max-guards-per-cycle: 10` にして `/bg reload` を実行する。全護衛の追従・警備が時間差で動き、特定の護衛だけが永久に止まらないことを確認する。11体を用意できない場合は、まず10体以下で従来どおり動くことだけ確認する。確認後は100へ戻す。
4. **個人設定**: `/bg command` の「個人設定」を開き、通知をチャット、GUI音を切、照準表示を切、一覧初期順を近い順へ変更する。クリックごとに表示が切り替わり、`players.yml` の `version: 4` と `settings` に残ることを確認する。再ログイン・再起動後も値が残ることを確認する。
5. **個人設定の反映**: 護衛のモードを変え、チャットに結果が出てタイトルが出ないことを確認する。GUI音が鳴らず、護衛に照準を合わせても画面下部の情報が出ないことを確認する。護衛一覧を開き、近い順から始まることを確認する。設定を継承へ戻すとサーバー設定に従うことを確認する。
6. **既存データ**: 以前の `players.yml` にあるガイド履歴、仲間、相棒が残っていることを確認する。`/bg friend list` と護衛詳細の相棒表示を使える。

## 未実施と引き継ぎ

開発担当はテスト、ビルド、Spigotサーバー起動を行っていない。利用者の手動確認結果は日時と成否を本節へ追記する。護衛巡回の上限は定期AI処理を対象とし、全ての保存・チャンク管理・整合処理を一定時間内に抑える保証ではない。
