# 護衛種類追加の計画・進行記録（2026-09-21）

## 目的・設計

追加入力「もっと追加してほしい」により、第2弾としてオオカミ、シロクマ、シルバーフィッシュ、エンダーマイト、村人ゾンビの5種類を追加し、最終的な初期候補を21種類にする。第1弾の記録・手順は以下に保持する。

### 第2弾の計画

1. 第1弾の変更を保持し、config.ymlとJavaの既定リストへ5種類を追記する。
2. 日本語名と特徴を追加し、既存のメッセージ補完を利用する。
3. READMEと本記録へ反映手順・種類固有の確認項目を追加する。
4. ソース差分の目視確認のみ行う。テスト・ビルド・サーバー起動はユーザーが実施する。

### 第2弾の既存サーバー設定

第1弾と同じJar更新手順に加え、サーバー側config.ymlの既存allowed-mobs一覧へ、次の未登録の行を追加する。反映はサーバー起動または新Jar導入後の`/bg reload`で行う。

```yaml
  - WOLF
  - POLAR_BEAR
  - SILVERFISH
  - ENDERMITE
  - ZOMBIE_VILLAGER
```

### 第2弾の手動確認

1. 召喚画面で新しい5種類の名前と説明が読めることを確認する。
2. `/bg summon wolf`、`/bg summon polar_bear`、`/bg summon silverfish`、`/bg summon endermite`、`/bg summon zombie_villager`を1回ずつ実行する。各1体が一覧に加わり、Tab補完にも候補が出れば成功。
3. 各種類で追従・待機・警備、回復、呼び戻しを試す。追従でついてくる、待機で残る、警備で指定場所を守る、回復でHPが戻る、呼び戻しで近くへ移動することを確認する。オオカミはまず手なずけていない個体で確認する。手なずけた個体を使う場合は立たせて確認する。
4. 所有者が敵を攻撃し、各護衛が加勢すること、所有者や同じ所有者の護衛を攻撃しないことを確認する。狭い場所ではなく、広い平地で1種類ずつ行う。
5. サーバーを停止・再起動し、種類・名前・モードが残ることを確認する。エンダーマイトは時間を置いた後も一覧と実体が一致することを確認する。
6. シルバーフィッシュは石材の近くで待機させ、ブロックへ潜伏せず実体が残ることを確認する。通常のシルバーフィッシュにはこの制御が適用されないことも確認する。村人ゾンビの治療後も護衛を継続する処理は追加していないため、通常の護衛運用中は治療を行わない。変身後の契約引き継ぎは今回の範囲外。
7. 第1弾と同様に、許可一覧から1種類を外すと召喚・勧誘が拒否されることと、既存種類が使えることを確認する。

### 第2弾の進行状況

- 設計・既存処理の調査：完了。

初期候補12種類にアイアンゴーレム、スノーゴーレム、ラヴェジャー、ゾグリンを加え、16種類にする。種類別の独自戦闘AIは追加せず、既存のMobターゲット制御、移動、味方判定、保存処理を利用する。スノーゴーレムは雪玉による支援役として説明し、通常の敵へのダメージを保証しない。

## 既存サーバーへの反映

1. サーバーを停止し、plugins/BodyGuardフォルダーと現在のJarをバックアップする。
2. プロジェクトのbuild.batをコマンドプロンプトから実行し、target/BodyGuard.jarをサーバーへ入れ替える。
3. サーバー側のplugins/BodyGuard/config.ymlをメモ帳等で開き、既存のallowed-mobs一覧の末尾へ次の4行を追加して保存する。allowed-mobs自体をもう1つ作らず、既存項目と同じ字下げにする。

```yaml
  - IRON_GOLEM
  - SNOW_GOLEM
  - RAVAGER
  - ZOGLIN
```

4. サーバーを起動する。新Jarの導入後に設定だけ変更した場合は、管理者が/bg reloadで反映できる。

既存の許可リストは自動拡張しない。管理者が禁止した種類を更新で有効にしないため。messages.ymlは置換不要で、新しいキーがなければ同梱の表示を利用する。

## 初心者向け手動確認（ユーザーが実施）

検証用サーバーの広い平地で、まずOPプレイヤーで確認する。

1. `/bg`の召喚画面を開く。追加4種類が日本語で表示され、カーソルを合わせると攻撃タイプと特徴が表示されることを確認する。
2. `/bg summon iron_golem`、`/bg summon snow_golem`、`/bg summon ravager`、`/bg summon zoglin`を1回ずつ実行する。それぞれ1体増え、日本語の種類名と番号が付くことを確認する。`/bg summon `の後でTabを押し、新種類が候補に出ることも確認する。
3. 各種類の詳細画面から追従・待機・警備を順に選ぶ。追従では移動したプレイヤーについてきて、待機では元の位置に残り、警備では指定地点の周囲を守ることを確認する。
4. 敵を1体ずつ用意し、所有者が攻撃する。近接3種類は接近して攻撃すること、スノーゴーレムは雪玉を投げることを確認する。雪玉は一般の敵へダメージを与える主力攻撃として判定しない。所有者と他の護衛が攻撃されないことも確認する。
5. 通常の新種類Mobを用意して見ながら`/bg recruit`を実行し、一覧に追加されることを確認する。追加した護衛を再起動後も一覧で確認できることを確認する。
6. 検証用config.ymlから追加種類を1つ外して`/bg reload`を実行する。その種類が召喚候補・Tab候補から消え、コマンドでの新規召喚も拒否されることを確認する。終了後は設定を戻す。
7. 既存のゾンビも召喚し、以前と同じ操作ができることを確認する。

## 制約・引き継ぎ

Mobの通常AIや環境による挙動はそのまま。大型Mobには広い移動経路が必要。新規の独自攻撃、環境ダメージ無効化、保存形式の変更は含まない。ゲーム内での追従・攻撃・再起動後の復元は未確認。
