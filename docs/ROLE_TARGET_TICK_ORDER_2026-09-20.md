# 役職保護の対象更新と戦闘判定の順序修正

作成日: 2026-09-20

## 目的と原因

役職保護中の護衛について、対象プレイヤーの変更や失効が起きた周期に古い戦闘対象を使用しないようにする。従来の `GuardTask.tickGuard()` は `validateCurrentTarget()` の後で `refreshProtectionTarget()` を呼んでいた。後者は対象変更時に戦闘状態とMobの攻撃対象を消すため、先に取得したローカル変数 `target` と最新状態が食い違う可能性があった。

## 計画と進捗

| 段階 | 作業 | 状態 |
| --- | --- | --- |
| 1 | 対象更新、戦闘状態の消去、各モードへの引き渡しをコードで確認 | 完了 |
| 2 | ROLEの場合は保護対象を更新してから戦闘相手を検証。対象なしなら戦闘判定を省略 | 完了 |
| 3 | OWNERの場合は従来どおり戦闘相手を検証してモード処理へ渡す | 完了 |
| 4 | 差分の静的確認 | 完了 |
| 5 | ビルドとゲーム内確認 | 未実施。利用者が実施する |

## 変更範囲

- `GuardTask.tickGuard()` の処理順だけを変更した。
- 役職選択、保存形式、候補選定、OWNERモードの判定規則は変更していない。

## 利用者による手動確認

1. サーバーを停止して新しいJarへ入れ替え、起動する。コンソールにBodyGuardの起動エラーがないことを確認する。
2. プレイヤーAの護衛に `/bg protect king` を設定し、king権限を持つプレイヤーBを近くに置く。護衛がBを保護することを確認する。
3. Bのking権限を外すかBをログアウトさせる。別のking候補Cがいれば、護衛がCへ切り替わることを `/bg protect status` で確認する。候補がいなければ護衛が待機することを確認する。
4. 切り替え直前に護衛を敵対Mobとの戦闘状態にし、切り替え後の護衛が古い戦闘相手を追い続けないことを確認する。
5. `/bg protect owner` に戻し、通常の追従・待機・警備と戦闘が従来どおり動くことを確認する。

## 引き継ぎ

コードから確認した順序上の不整合に対する修正であり、実機での再現・修正確認は未実施。利用者の手動確認結果をこの文書に追記する。テスト、Mavenビルド、サーバー起動は開発担当では実施していない。
