# 利用者向け 手動確認手順

この文書は**実装完了後に利用者が行う確認**の計画です。計画作成時点では新機能の多くが未接続です。担当AIはテスト、ビルド、サーバー起動を行っていません。

## 1. 最初の準備

1. 確認用のSpigot 1.21.8サーバーを用意します。Javaは21を使います。
2. サーバーを停止し、`plugins/BodyGuard`フォルダとワールドを別の場所へコピーしておきます。
3. Windowsの**コマンドプロンプト**で次を実行します。

```bat
cd /d C:\Users\USER\Documents\Plugin\BodyGuard
build.bat
```

4. 成功したら `target\BodyGuard.jar` を確認用サーバーのpluginsへコピーします。同じプラグインの別名Jarを二重に置かないようにします。
5. サーバーを起動し、コンソールのエラーを確認します。失敗時はここで止め、エラーの全文を担当者へ渡します。
6. 平らで明るい場所に護衛を2～3体用意し、名前を付けます。強いMobや大量の護衛は基本確認の後にします。
7. `/bg help`、`/bg list`、`/bg status`が使えることを確認します。

この文書の秒数はサーバーが通常速度で動く場合の目安です。護衛数が多い、またはサーバーが遅い場合は長くなります。

## 2. 最小確認（まずここまで）

| ID | 操作 | 成功の目安 |
|---|---|---|
| A01 | 広い床で3体を連れて歩き、止まる | 護衛が別々の位置へ集まり、所有者の視線を変えただけで大きく入れ替わらない |
| A02 | `/bg tp`、詳細画面の単体呼び戻しを使う | 移動した数が合い、単体操作で他の護衛は移動しない |
| A03 | 護衛を見て `/bg policy passive`、敵を近くに置く | 護衛は攻撃しない。敵からのダメージまで無効になるわけではない |
| A04 | `/bg policy retaliate`、敵の近くへ行く | 近いだけでは先に攻撃せず、護衛または保護対象が攻撃されると反撃する |
| A05 | 通常の「待機」にして自分が離れる | 勝手に追従や復帰を開始せず、元の待機地点を守る |
| A06 | 巡回を2地点登録し開始する（次節） | 2地点を順に回り、停止するとその位置で警備する |
| A07 | 名前・方針・巡回地点を設定して正常停止→再起動 | 設定が残り、護衛が増殖したり契約が消えたりしない |
| A08 | `/bg status server` | 数値の項目が表示され、未測定は記録なし、平均と最大が区別される |

## 3. 巡回を実際に登録する

以下のUUIDは `/bg list`や詳細の巡回情報で取得した**自分の護衛UUID**へ置き換えます。角括弧は入力しません。

1. 所有者保護にして、平らな場所の地点Aに立ちます。
2. `/bg patrol add 護衛UUID` を実行します。
3. 同じワールドで5～10ブロック離れた地点Bへ歩きます。
4. `/bg patrol add 護衛UUID` を実行します。
5. `/bg patrol list 護衛UUID` でA・Bの2地点を確認します。
6. `/bg patrol start 護衛UUID` を実行します。
7. 護衛がA→B→Aと回ることを確認します。地点付近では少し待ちます。
8. `/bg patrol stop 護衛UUID` を実行し、地点情報が残ったまま固定警備になることを確認します。

UUIDを省略すると、見ている自分の護衛が対象です。遠い地点を登録するときはUUID指定を使います。未読み込みの護衛は変更できないため、最初は近い範囲で行ってください。

## 4. 動きと戦闘の詳しい確認

| ID | 確認すること | 手順・期待結果 |
|---|---|---|
| M01 | 壁で停止した護衛 | 所有者と護衛を10～15m離し、間に高さ3ブロック程度の壁を置く。広い足場を用意して待つ。横移動または安全な位置への復帰が起こる。通常の遠距離復帰の閾値未満で試す |
| M02 | 復帰先がない | 周囲が狭い/床のない確認用の場所で、安全先不足の案内が出ることを見る。空中や壁内へ強制移動しない。床を広げると再試行で復帰する |
| M03 | モード変更の直後 | 引っかかり判定中にSTAYへ切り替える。古い所有者位置への復帰が残らない |
| M04 | 大小の護衛の集合 | Skeleton等と大きい護衛を混ぜて広い床で集合。相互の体積が重ならない。狭い床では失敗/空き不足が表示され、成功数が水増しされない |
| M05 | 配置が変わらない | 一覧をHP順/近い順に切替、所有者の視線を回す。画面順や視線だけで配置枠が入れ替わらない |
| M06 | 多数の配置 | 基本確認が終わった後に少しずつ増やす。有限範囲の空きがなくなったら待機/失敗になり、同じ座標に大量移動して成功扱いにしない |
| M07 | 配置無効 | formation.enabled=falseでreload。従来の追従/呼び戻しへ戻る。確認後trueへ戻す |
| M08 | ASSIST | `/bg policy assist`。敵に近づくだけでは攻撃せず、自分が敵を攻撃すると支援。元の支援設定がfalseなら支援しない |
| M09 | INTERCEPT | `/bg policy intercept`。合法な敵対Mobが範囲内へ来ると迎撃。近くの一般プレイヤーや仲間を距離だけで攻撃しない |
| M10 | LEGACY | `/bg policy legacy`。従来の追従/待機/警備の標的取得規則に戻る。新しい撤退・配置の設定は別に有効 |

| M12 | 味方 | 所有者・friend登録者・同所有者護衛を近くへ置く。従来の味方設定に従い、迎撃方針で無差別攻撃しない |
| M13 | PvP設定 | defend-against-players=falseにして、確認用の別プレイヤーとの防衛を試す。護衛がプレイヤーへの禁止攻撃を開始しない |
| M14 | 戦闘時間 | 確認用設定でmax-secondsを5～10にする。同じ敵へ攻撃支援を繰り返しても一定時間後に撤退する。退却中にすぐ敵へ戻らない |
| M15 | 保護対象との距離 | 敵に護衛を誘導させ、保護中心から制限を越えると帰還する。警備では既存の警備半径も越え続けない |
| M16 | 視認喪失 | 敵との間を壁で遮る。unseen-seconds程度見失ったら追跡をやめる。再び見えた場合は最後の視認から計測される |
| M17 | 敵切替 | A/Bの敵へ支援対象を切り替え続ける。戦闘エピソードが無限に延びず撤退する |
| M18 | 射手 | 弓SkeletonまたはクロスボウPillagerへ敵を接近させる。安全な床があれば短く後退し、射撃を継続する |
| M19 | 射手の壁・崖 | 背後に壁/崖がある場所。危険な後退をせず、通常AIへ任せる。guard半径外へ後退し続けない |
| M20 | 装備条件 | 可能な確認環境で弓を外す/近接装備へ変える。遠距離の後退補助が止まる。AIが自動で弓を配らない |
| M21 | ROLE | 権限を持つ選択対象を保護させる。所有者と対象が別方向へ移動したとき、対象側の配置・防衛・撤退先を使う |

| M23 | 巡回中の戦闘 | 巡回の途中で敵を迎撃。戦闘中に地点番号だけ進まず、終了後は現在地点へ戻り巡回を続ける |

| M27 | 地点編集 | removeで末尾1点だけ消え、2点未満なら巡回停止。clearで地点と巡回を解除。他護衛のルートは残る |
| M28 | 地点の誤入力 | 1点だけでstart、同位置連続追加、別ワールド追加、17点目を試す。理由付きで拒否し、元の有効ルートを壊さない |
| M29 | 未読込の巡回先 | 読み込み範囲外への経路では保留理由が出る。経路全体を勝手に大量ロードしない |

## 5. 負荷・保存・権限の確認

数が多い確認は基本機能が正常に動いてから行います。体数を急増させず、段階的に増やしてください。

| ID | 手順 | 成功の目安 |
|---|---|---|
| P01 | max-guards-per-cycle=10、管理records=2、可能なら護衛11体以上 | どの護衛にも順番が回り、処理待ちが診断に出る。設定は終了後に戻す |
| P02 | FOLLOW/戦闘と遠方STAYを混ぜる | 移動・戦闘が優先されても遠方STAYの更新が永久停止しない |
| P03 | 上限を小さくしたまま護衛を追加・解除・再勧誘 | 古い世代の指示が復活せず、キューが操作のたびに増え続けない |
| P04 | cycle-budget-ms=1.0程度で診断を見る | 仕事が繰り越される。単発の保存やロードの超過は実測値と超過回数へ出る。「必ず1ms以内」になる確認ではない |
| P05 | 護衛を異なるチャンクへ置き、管理上限を小さくする | ticket数が設定に従い、管理が段階的に進む。有効なticketが毎周期無意味に入れ替わらない |
| P06 | 計画中に所有者ログアウト/護衛移動/reload | 古い計画から不要なチャンクを読み込み続けない。所有者上限/全体上限/確認中の案内が区別される |
| P07 | 護衛を連れてチャンクを何度か往復する | 見つかった護衛が遅い古い観測で所在不明へ戻らない。tacticsと名前が残る |
| P08 | 通常の移動とチャンク読み込みを続ける | 通常保存が操作ごとに即連発せず、診断の待ち→成功へ進む。変更が永久未保存にならない |
| P09 | autosave-seconds=0にし、名前/方針を明示変更 | 明示変更は保存される。通常位置の定期保存は停止する。終了後は元の値へ戻す |
| P10 | 方針・巡回・名前を設定し正常再起動 | すべて保持。巡回番号だけは先頭から再開する仕様。旧データのお気に入り・相棒・友達も残る |
| P11 | 自分の護衛を解除し、その通常Mobを再勧誘 | 同じUUIDでも新契約として扱われ、古い攻撃・巡回・削除指示が発動しない |
| P12 | 普通のプレイヤーで上限到達 | 召喚/勧誘が拒否され、理由がGUI・コマンドで一致する |
| P13 | OP個人免除true/falseを切替 | trueは召喚の個人枠を免除、falseは適用。勧誘の個人枠はどちらでも適用 |
| P14 | max-guards-serverを小さい正数にする | OPを含め新規追加が全体上限で止まる。既存数未満へ下げても今いる護衛を削除しない |
| P15 | 上限到達後にサーバー再起動 | 既存護衛の読み込み復旧を新規召喚扱いで拒否しない |
| P16 | 警告値を到達しやすい数にする | 閾値到達を通知するが毎周期/毎クリックに連発しない。閾値未満へ減らしてから再到達すると再通知できる |
| P17 | 通常プレイヤーから管理者診断を実行 | 権限不足を表示し、他人の護衛情報を出さない |
| P18 | policy/patrol権限なし、他人のUUID指定 | GUIとコマンドの両方で変更不可。表示名やUUIDを知っていても操作できない |
| P19 | GUIで数字キー・ドラッグ・持ち替え | 新しい方針/巡回操作が誤発動せず、見本アイテムを取り出せない |
| P20 | 新設定の不正な数値・messages構文エラーでreload | 旧設定/旧messagesを保持し、一方だけ新設定にならない。確認後ファイルを戻す |
| P21 | 管理GUIとstatus serverを比較 | 平均/最大/直近の意味が一致し、記録なしと0を区別する。診断を開くことで遠方をロードしない |

### 保存障害は無理に発生させなくて構いません

通常の確認でファイル破損や保存拒否をわざと起こす必要はありません。実際に保存エラーが出た場合は、成功通知になっていないか、`/bg status server`の理由とコンソールログを記録してください。保存保護で停止した状態を、ファイル削除や再起動の繰り返しで無理に解除しないでください。

復旧手順の実験は、別コピーのサーバーで担当者と対象を確認した場合だけ行います。元データを破損させるコマンドは本書に含めません。
