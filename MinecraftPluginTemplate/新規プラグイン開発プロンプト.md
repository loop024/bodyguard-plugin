# ChatGPT Work用・Minecraftプラグイン作成プロンプト

下のプロンプトをChatGPT Workへ貼り付けて使います。毎回変更するのは、最初の「今回作るプラグイン」欄だけです。

ChatGPT Workのプロジェクトへこのテンプレートフォルダを追加しておくと、複数のプラグインを同じ開発方針で作れます。

~~~~text
あなたはMinecraftサーバープラグインを完成品まで実装するJava開発者です。
企画だけで終わらず、新しいプラグイン専用フォルダと、その中で動作に必要なファイルをすべて作成してください。

━━━━━━━━━━━━━━━━━━━━
【今回作るプラグイン】
━━━━━━━━━━━━━━━━━━━━

プラグイン名（半角英数字）: [例: AutoMessage]
メインコマンド（半角英小文字）: [例: automessage]
Javaパッケージ名: [未記入なら com.example.プラグイン名の小文字]
作者名: [作者名]
概要: [どんなプラグインか1～3行で書く]

必要な機能:
- [機能1]
- [機能2]
- [機能3]

追加の希望:
- [GUI、保存方法、メッセージ、権限など。なければ「なし」]

━━━━━━━━━━━━━━━━━━━━
【開発環境】
━━━━━━━━━━━━━━━━━━━━

- OS: Windows 10
- Java: 21
- Minecraft: 1.21.8
- API: Spigot API 1.21.8
- ビルド: Maven
- 文字コード: UTF-8
- バッチファイル: Windowsコマンドプロンプト形式（.bat）

━━━━━━━━━━━━━━━━━━━━
【必ず作るフォルダとファイル】
━━━━━━━━━━━━━━━━━━━━

現在の作業場所に「プラグイン名」と同じ名前の新規フォルダを作り、その中だけで開発してください。
ほかのプラグインや既存フォルダのファイルは変更しないでください。

最低限、次の構成を作ってください。機能が多い場合はcommand、listener、service、storage、gui、utilなどへ適切に分割してください。

プラグイン名/
├─ pom.xml
├─ build.bat
├─ README.md
├─ .gitignore
└─ src/
   └─ main/
      ├─ java/
      │  └─ Javaパッケージのパス/
      │     └─ プラグイン名.java
      └─ resources/
         ├─ plugin.yml
         ├─ config.yml
         └─ messages.yml（メッセージが複数ある場合）

━━━━━━━━━━━━━━━━━━━━
【pom.xmlの基準】
━━━━━━━━━━━━━━━━━━━━

以下のpom.xmlを基準として必ず使用してください。
`PLUGIN_NAME`は実際のプラグイン名、`GROUP_ID`はJavaパッケージに合わせて置換してください。
不要な変更はせず、追加ライブラリが必要な場合だけdependenciesへ追記してください。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <groupId>GROUP_ID</groupId>
    <artifactId>PLUGIN_NAME</artifactId>
    <version>1.0.0</version>
    <packaging>jar</packaging>

    <name>PLUGIN_NAME</name>

    <properties>
        <java.version>21</java.version>
        <spigot.version>1.21.8-R0.1-SNAPSHOT</spigot.version>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <project.reporting.outputEncoding>UTF-8</project.reporting.outputEncoding>
    </properties>

    <build>
        <finalName>${project.artifactId}</finalName>
        <defaultGoal>clean package</defaultGoal>
        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.13.0</version>
                <configuration>
                    <release>${java.version}</release>
                    <encoding>${project.build.sourceEncoding}</encoding>
                </configuration>
            </plugin>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-shade-plugin</artifactId>
                <version>3.6.0</version>
                <executions>
                    <execution>
                        <phase>package</phase>
                        <goals>
                            <goal>shade</goal>
                        </goals>
                        <configuration>
                            <createDependencyReducedPom>false</createDependencyReducedPom>
                        </configuration>
                    </execution>
                </executions>
            </plugin>
        </plugins>
        <resources>
            <resource>
                <directory>src/main/resources</directory>
                <filtering>true</filtering>
            </resource>
        </resources>
    </build>

    <repositories>
        <repository>
            <id>spigotmc-repo</id>
            <url>https://hub.spigotmc.org/nexus/content/repositories/snapshots/</url>
        </repository>
    </repositories>

    <dependencies>
        <dependency>
            <groupId>org.spigotmc</groupId>
            <artifactId>spigot-api</artifactId>
            <version>${spigot.version}</version>
            <scope>provided</scope>
        </dependency>
    </dependencies>
</project>
```

━━━━━━━━━━━━━━━━━━━━
【build.batの要件】
━━━━━━━━━━━━━━━━━━━━

- 利用者がMavenコマンドを入力しなくても、build.batをダブルクリックするだけでビルドできるようにする。
- 最初にスクリプト自身があるフォルダへ移動する。
- `mvnw.cmd`、`MAVEN_HOME`、PATH上の`mvn`、IntelliJ IDEA付属Mavenの順で自動検索する。
- `mvn clean package`を実行する。
- 成功時は`target/プラグイン名.jar`の場所を日本語で表示し、targetフォルダを開く。
- 失敗時は日本語で分かりやすく案内し、ウィンドウがすぐ閉じないようにpauseする。
- PowerShell専用の処理は使わない。

━━━━━━━━━━━━━━━━━━━━
【実装ルール】
━━━━━━━━━━━━━━━━━━━━

- Javaパッケージ、フォルダパス、メインクラス、pom.xml、plugin.ymlの名前を完全に一致させる。
- plugin.ymlには、すべてのコマンド、エイリアス、権限、usageを登録する。
- 権限の初期値は、一般機能はtrue、管理機能はopを基本とする。
- プレイヤー向けメッセージは日本語にし、色付きで読みやすくする。
- 利用者が変更したい数値や文言は、可能な限りconfig.ymlまたはmessages.ymlへ分離する。
- config.ymlには初心者にも意味が分かる日本語コメントを付ける。
- reloadコマンドを作る場合は、設定を安全に再読み込みする。
- Player専用コマンドをコンソールから実行した場合は、例外を出さず案内を表示する。
- 権限不足、引数不足、不正な値、対象不在、プレイヤー退出、ワールド不在を安全に処理する。
- イベント登録、タスク、ファイル保存などは、プラグイン停止時に安全に終了する。
- 重いファイル処理、通信、データベース処理をサーバーのメインスレッドで長時間実行しない。
- 非同期処理からBukkit APIを直接操作しない。
- データ保存が必要な機能は、サーバー再起動後にも復元できるようにする。
- UUIDでプレイヤーやEntityを管理し、表示名だけを識別子として使わない。
- 外部ライブラリを追加する場合は、なぜ必要かREADME.mdへ書く。
- サーバーが提供するAPIは`provided`、JARへ同梱するライブラリは通常のdependencyとして扱う。
- 同梱ライブラリで競合の恐れがある場合は、maven-shade-pluginのrelocationを設定する。
- `/reload`の使用を推奨しない。導入・更新時はサーバー再起動を案内する。
- APIに存在するか不明なメソッドを想像で使用しない。
- 未実装、ダミー処理、TODOだけのファイルを残さず、指定機能を最後まで実装する。

━━━━━━━━━━━━━━━━━━━━
【作業方法】
━━━━━━━━━━━━━━━━━━━━

1. 最初に要件を整理する。
2. 通常の細かい判断は、安全で使いやすい内容を選んで作業を進める。
3. 保存方式やゲームバランスなど、後から変更しにくい重大な不明点だけ質問する。
4. 新規フォルダと全ファイルを実際に作成する。回答にコード例を載せるだけで終わらない。
5. 私が自分で確認するため、テスト、Mavenビルド、サーバー起動は実行しない。
6. 完成後、作成したフォルダ、主要ファイル、導入方法、初心者向け動作確認手順を日本語で説明する。
7. ChatGPT Workからローカルフォルダへ直接保存できない場合は、同じ構成を維持したダウンロード可能なZIPとして渡す。

README.mdには必ず次を記載してください。

- プラグインの概要
- コマンド一覧
- 権限一覧
- config.ymlの設定説明
- ビルド方法（build.batをダブルクリック）
- 導入方法（JARをサーバーのpluginsへ入れて再起動）
- 初心者向けの動作確認手順
- よくあるエラーと対処方法

以上の条件で、今回指定したプラグインを完成させてください。
~~~~

## おすすめの使い方

1. ChatGPTでMinecraftプラグイン専用のプロジェクトを作ります。
2. このテンプレートフォルダをプロジェクトのファイルとして追加します。
3. プラグインごとに新しいChatGPT Workを開始します。
4. 上のプロンプトをコピーし、「今回作るプラグイン」だけ書き換えて送ります。
5. 作成されたフォルダをMinecraftサーバーの開発フォルダへ保存します。
