# BodyGuard

敵対モブをプレイヤー専属の護衛にして連れ歩ける、Spigot用プラグインです。護衛の所有者判定、既存の戦闘AI、攻撃力、移動速度、保存方式は維持し、プレイヤーが一覧画面から状態を確認・操作しやすい構成にしています。

## 対応環境

- Minecraft Java Edition 1.21.8
- Spigot 1.21.8
- Java 21
- Windows 10
- 必須の外部プラグイン、リソースパック、Paper専用API、NMSはありません

## インストール

1. このプロジェクトでJarを作成します。手順は「ビルドとJarの入れ替え」を参照してください。
2. サーバーを停止した状態で、作成した `target/BodyGuard.jar` をサーバーの `plugins` フォルダへコピーします。
3. 既存のBodyGuardのJarがある場合は、同じファイルを置き換えます。
4. サーバーを起動し、ゲーム内で `/bg help` を実行します。

初回起動時に `plugins/BodyGuard/config.yml`、`messages.yml`、`guards.yml` が作成されます。既存の設定ファイルやメッセージファイルは丸ごと上書きしません。新しいキーが既存ファイルにない場合は、安全な既定値とプラグイン内の日本語フォールバックを使います。

## 基本操作

プレイヤーが `/bg` または `/bg menu` を実行すると、54スロットの護衛一覧GUIが開きます。コマンドから開く方法は残っています。

一覧では、護衛カードのクリック方法によって次の操作ができます。

- 左クリック: 45スロットの詳細画面を開く
- 右クリック: 追従、待機、警備の順に次のモードへ変更
- Shift＋左クリック: その護衛1体だけを呼び戻す
- Shift＋右クリック: その護衛1体だけを回復

解除と名前変更は、誤操作を避けるため詳細画面から行います。また、次の条件をすべて満たすと、護衛を直接しゃがみ＋右クリックして詳細画面を開けます。

- 自分が所有する護衛である
- プレイヤーがしゃがんでいる
- メインハンドとオフハンドの両方が空である
- `bodyguard.use` または `bodyguard.admin` を持っている

空の手を使うのは、通常のアイテム使用や通常Mobへの右クリックを妨げないためです。他人の護衛や通常Mobへの右クリックは変更しません。メインハンドのイベントだけを受け付けるため、オフハンドとの二重表示も起こしません。

## コマンド

| コマンド | 説明 |
| --- | --- |
| `/bg help` | コマンド一覧を表示 |
| `/bg` / `/bg menu` | 護衛一覧GUIを開く（プレイヤーのみ） |
| `/bg command` | 27スロットの簡易司令メニューを開く |
| `/bg item` | 保護されたメニュー専用アイテムを受け取る（1個まで） |
| `/bg summon <mob>` | 対応Mobを召喚して護衛にする |
| `/bg recruit` | 見ている既存の対応Mobを護衛にする |
| `/bg release` | 見ている自分の護衛を通常Mobに戻す |
| `/bg releaseall confirm` | 自分の護衛をすべて解除 |
| `/bg list` | 自分の護衛一覧をチャット表示 |
| `/bg tp` | 自分の護衛を周辺へ呼び戻す |
| `/bg mode follow` | プレイヤーを追従 |
| `/bg mode stay` | 現在位置で待機 |
| `/bg mode guard` | 現在位置を中心に警備 |
| `/bg rename <名前>` | 見ている護衛の名前を変更。既存の1～64文字制限と色指定を維持 |
| `/bg heal` | 自分の護衛を全回復 |
| `/bg reload` | 設定を再読み込み（管理者） |

`recruit`、`release`、`mode`、`rename` は、既存コマンドの仕様どおり、5～10ブロック程度の範囲で対象Mobを見て実行してください。

## 簡易司令メニュー

`/bg command` または専用メニューアイテムの右クリックで、27スロットの司令メニューを開きます。`/bg` と `/bg menu` は従来どおり護衛一覧を開きます。

| スロット | 内容 |
|---:|---|
| 4 | 護衛総数、操作可能数、未読み込み数 |
| 9 / 11 / 13 | 全員追従／全員待機／全員警備 |
| 15 | 読み込み済みの護衛を全員集合 |
| 17 | 読み込み済みの負傷者を回復 |
| 18 | 護衛一覧 |
| 20 | 新規召喚 |
| 22 | 管理 |
| 24 | 個人設定。現在は準備中のため操作不可 |
| 25 | 直前の一括操作結果 |
| 26 | 閉じる |

一括操作は未読み込みチャンクを強制ロードせず、実行時にも所有者と権限を確認します。結果欄には成功数、未読み込み数、失敗数を分けて表示します。回復では全回復済みの護衛も対象外として表示します。

## 初回ガイド

初めて `/bg`、`/bg menu`、`/bg command`、専用コンパスのいずれかを使うと、3ページの初回ガイドを表示します。護衛の迎え方、勧誘、専用コンパス、一覧のクリック操作、追従・待機・警備の違いを順番に確認できます。

- 「完了」「ガイドを終了」は読了として保存します。
- 「次回から表示しない」は非表示として保存します。
- 閉じるボタンで閉じただけでは保存せず、次回も表示します。
- 一覧左上の「操作ガイド」または司令メニューの「操作ガイド」からいつでも再表示できます。
- 状態はプラグインフォルダーの `players.yml` に保存され、再ログインや再起動後も維持されます。

既存プレイヤーへの自動表示が不要な場合は `tutorial.show-to-existing-players: false`、全員への自動表示を止める場合は `tutorial.enabled: false` にします。手動での再表示は自動表示設定を無効にしても利用できます。

## 一覧画面

一覧は54スロットです。スロット番号は0始まりです。

| 位置 | 内容 |
| --- | --- |
| 0 | 操作ガイド。空の手でしゃがみ＋右クリックする方法も表示 |
| 2 | 絞り込み。すべて、負傷中、追従中、待機中、警備中、状態を確認できない護衛を順に切り替え |
| 4 | 護衛数、上限、負傷数、状態を確認できない数、召喚可能数、表示対象数 |
| 6 | 並べ替え。標準、近い順、HP割合が少ない順を順に切り替え |
| 8 | 追従・待機・警備の説明 |
| 9～44 | 護衛一覧 |
| 45 | 前のページ |
| 46 | 召喚 |
| 47 | 全員を呼び戻す |
| 48 | 全員を回復 |
| 49 | 直前の操作結果 |
| 50 | 管理。全員の契約解除はここから確認画面へ進む |
| 51 | 手動更新 |
| 52 | 次のページ |
| 53 | 閉じる |

各護衛カードは「種類、HP、HPバー、行動、距離または状態」の順で表示し、末尾にクイック操作を案内します。「表示対象3体／全8体」のように、絞り込み後の件数と護衛全体の件数を分けて表示します。条件に合う護衛が0体の場合は初回召喚案内を表示せず、「条件に合う護衛がいません」と「条件を解除」を表示します。護衛自体が0体の場合だけ、次の2つの案内を表示します。

- 「最初の護衛を召喚」: 召喚候補画面を開きます。召喚権限がない場合は実行時に理由を表示します。
- 「野生のMobを仲間にする方法」: 対応Mobを見て `/bg recruit` を実行し、成功するとそのMobが護衛になることを案内します。勧誘権限がない場合は理由を表示します。

### 絞り込みと並べ替え

HPを取得でき、現在HPが最大HPより少ない護衛だけを「負傷中」に数えます。HP不明の護衛を負傷・健康のどちらにも推測しません。「状態を確認できない護衛」は、現在Entityを確認できない護衛です。別ワールドにいるだけで状態不明にはしません。読み込み済みなら、別ワールド名を表示します。

「近い順」は同じワールドで距離を比較できる護衛を先にし、別ワールド・未読み込み・距離不明を末尾にします。「HP割合が少ない順」は残りHPの数値ではなく、現在HP÷最大HPで比較します。不明値を0として扱いません。同順位は一覧の元の順番を維持します。

詳細画面や管理画面から一覧へ戻ると、ページ、絞り込み、並べ替えを維持します。絞り込み・並べ替えを変更した場合は先頭ページに戻ります。

## 召喚画面

候補ごとに、`messages.yml` の `mob-features` から攻撃タイプと短い特徴を表示します。Skeleton、Stray、Boggedは弓、Pillagerはクロスボウなど、通常AIや装備条件に依存する特徴には条件を添えています。未知の追加Mobには「通常AIに従う」という汎用説明を使い、保証していない能力を断言しません。

召喚直前にも、権限、`allowed-mobs`、対応Mob、護衛数上限を再確認します。召喚不可の場合は、特徴説明に加えて権限不足・設定・上限などの理由を表示します。

## 護衛詳細画面

詳細画面は45スロットです。対象UUIDを保持して操作し、表示名や一覧番号だけでは対象を識別しません。

詳細画面から各護衛を複数体「お気に入り」に登録でき、所有者ごとに1体だけ「相棒」を設定できます。お気に入りは標準の一覧で先頭へ移動し、「お気に入り」フィルターでも絞り込めます。お気に入りには `☆`、相棒には `★ 相棒` を表示し、どちらもアイコンが控えめに光ります。相棒が死亡または解除された場合は相棒設定を自動解除し、オンラインの所有者へ通知します。未読み込み中でも設定は保持され、別の護衛へ勝手に移りません。

| スロット | 内容 |
| --- | --- |
| 4 | 対象護衛の名前、種類、モード、HP、バー、割合、距離または状態 |
| 10 | 追従。リードを表示 |
| 13 | 待機。金床を表示 |
| 16 | 警備。盾を表示 |
| 19 | 名前変更 |
| 22 | この護衛を回復 |
| 25 | この護衛を呼ぶ |
| 31 | この護衛の契約を解除 |
| 36 | 一覧に戻る |
| 40 | 直前の操作結果 |
| 42 | 手動更新 |
| 44 | 閉じる |

選択中のモードも、リード・金床・盾の元のアイコンを維持します。名前に「選択中」を付け、文字と控えめな光る演出で区別します。同じモードを押しても不要な状態変更や通知を繰り返しません。

### GUIからの名前変更

1. 詳細画面で「名前変更」をクリックします。
2. 標準の金床入力画面で、現在の名前を確認して新しい名前を入力します。
3. 結果スロットをクリックして確定します。
4. 同じ護衛の詳細画面へ戻ります。

入力欄は標準金床のGUI側制約に合わせて1～50文字です。空白だけの名前や上限超過は保存せず、理由を表示します。結果スロットを確定するまで保存せず、途中で閉じる・キャンセルする・入力欄を操作するだけでは変更しません。経験値や持ち物を消費せず、金床の見本アイテムや結果アイテムを取得できないようにしています。

既存の `/bg rename <名前>` は残しており、コマンド側の1～64文字制限と `&` 色指定の扱いを変更していません。GUI側だけが標準金床入力の1～50文字制限を案内します。死亡、解除、ログアウト、権限変更などで対象UUIDが使えなくなった場合は保存せず、安全に終了します。

### 単体回復と単体呼び戻し

「この護衛を回復」「この護衛を呼ぶ」は、詳細で選択しているUUIDの1体だけを対象にします。権限、所有者、護衛の存在、読み込み状態を実行時に再確認します。

- 単体回復は `bodyguard.heal` を使い、HPが実際に増えた場合だけ成功件数を1とします。全回復済みなら「すでに全回復しています」と表示します。
- 単体呼び戻しは `bodyguard.teleport` を使い、既存の全員呼び戻しと同じ安全な移動先と戦闘解除の処理を使います。
- 未読み込みの護衛を、この2つのGUI操作のために強制読み込みしません。
- 成功後も同じ護衛の詳細画面を開き、HP・距離・状態を更新します。他の護衛は操作しません。

## 自動更新と操作結果

一覧、召喚、詳細、管理画面は、標準で20tick（約1秒）ごとにHP・距離・状態・概要を更新します。自動更新は画面を閉じたり開き直したりしません。表示中の護衛UUIDとスロット位置は固定し、HP順・距離順でも自動更新だけで並べ替えません。護衛が死亡・解除された場合は、そのスロットに無効表示を残し、別の護衛を自動で詰めません。クリック時には現在の所有者・存在・権限・読み込み状態を再確認します。

手動更新、条件変更、ページ移動、画面を開き直す操作で一覧を再抽出します。解除確認画面と名前入力画面は自動更新しません。設定を再読み込みすると、更新タスクをいったん停止してから現在の設定で再起動します。

直前の操作結果は専用アイコンに短く表示し、数秒後に通常案内へ戻します。成功は緑、注意は黄、失敗は赤、通常案内と利用不能は灰色で区別します。結果の古い消去処理が新しい結果を消さないようにしています。自動更新では音を鳴らしません。成功と失敗は操作した本人だけに控えめな音で通知します。召喚・解除のワールド効果音は既存の `effects.enabled` で別に制御されます。

画面テーマは、護衛一覧が青・水色、召喚が紫・マゼンタ、管理が黄・橙、解除確認が暗い赤です。詳細画面は健康なら緑、軽傷なら黄、瀕死なら赤、状態不明なら灰色の背景になります。戻るは左下、閉じるは右下、更新は右下寄りに揃えています。

## 照準中のアクションバー

自分の護衛に照準を合わせている間だけ、画面下部に「名前｜モード｜HP」を表示します。目安は既存の対象選択と同程度の範囲で、壁越しのEntityは対象にしません。視線を外す、別のMobを見る、GUIを開くと表示を終了します。HP不明は不明と表示し、低HPは色と文字で分かるようにします。

他プラグインのアクションバー表示との完全な共存は保証しません。送信間隔を設け、表示内容が変わらない間や表示終了後の不要な空文字を連続送信しません。

## 名前の初期値と番号

同梱設定の新規護衛名は、例として「ゾンビ護衛 01」「ゾンビ護衛 02」の形式です。同じ所有者・同じ種類の護衛ごとに番号を採番し、削除や再起動後も保存した番号を使います。削除された護衛の番号を再利用するために、既存護衛の名前を変更することはありません。

`config.yml` の `display.default-name` でテンプレートを変更できます。

- `{mob_name}`: `messages.yml` の日本語Mob名
- `{number}`: 同じ所有者・同じ種類の連番（01のように2桁表示）
- `{owner}`: 既存テンプレート互換の所有者名
- `{mob}`: 既存テンプレート互換の英語Mob名

既存サーバーのカスタムテンプレートを無視しません。テンプレートに `{number}` がない場合も、互換性のため自動的に追加しません。既存の護衛名とユーザーが変更した名前は一括変更しません。詳細タイトルでは長い名前を安全に省略し、説明欄で全体を確認できます。

## 全解除と管理画面

一覧の「管理」から「全員の護衛契約を解除」を押すと、対象数、通常のMobに戻ること、敵対する可能性を表示した確認画面へ進みます。確認画面を開いた時点のUUID一覧を固定し、確認後に増えた護衛へ対象を広げません。実行時にも所有者、存在、読み込み状態、権限を再確認し、結果を「解除済み」「解除予約」「失敗」に分けて表示します。

未読み込みの護衛は同期的にチャンクを読み込まず、解除予約として `guards.yml` に保存します。対象チャンクが自然に読み込まれた時点で、元のMob設定を復元し、BodyGuard識別情報を削除して通常Mobへ戻します。解除予約はサーバー再起動後も維持され、一覧には「解除予約中」と表示されます。

全解除のキャンセルは管理画面へ戻り、単体解除のキャンセルは同じ護衛の詳細へ戻ります。確認画面を閉じるだけでは解除しません。

## Permissions

- `bodyguard.use` - `/bg` とGUIの使用
- `bodyguard.item` - メニュー専用アイテムの受け取り
- `bodyguard.summon` - 護衛の召喚
- `bodyguard.recruit` - 既存Mobの勧誘
- `bodyguard.release` - 護衛の解除
- `bodyguard.releaseall` - 全護衛の解除
- `bodyguard.mode` - モード変更
- `bodyguard.rename` - 名前変更
- `bodyguard.teleport` - 護衛の呼び戻し
- `bodyguard.heal` - 護衛の回復
- `bodyguard.reload` - 設定再読み込み（初期値はOPのみ）
- `bodyguard.admin` - 上記操作を管理者として許可

画面表示だけでなく、操作を実行する瞬間にも権限を確認します。

| `effects.gui-sounds.enabled` | `true` | GUI操作音の有効化 |
| `effects.gui-sounds.success-sound` | `UI_BUTTON_CLICK` | 成功音。SpigotのSound名 |
| `effects.gui-sounds.failure-sound` | `BLOCK_NOTE_BLOCK_BASS` | 失敗音。SpigotのSound名 |
| `effects.gui-sounds.volume` | `0.35` | GUI操作音の音量（0～1） |
| `effects.gui-sounds.success-pitch` | `1.25` | 成功音の音程（0.5～2） |
| `effects.gui-sounds.failure-pitch` | `0.75` | 失敗音の音程（0.5～2） |

新しい数値設定が不正または範囲外の場合は、プラグイン内の既定値へ戻します。設定再読み込みは `/bg reload` で行えます。既存の `messages.yml` にないキーも同梱フォールバックで動作します。Mob名は `mob-names`、召喚候補の説明は `mob-features` で変更できます。

## 初期対応Mob

Zombie、Skeleton、Husk、Stray、Drowned、Bogged、Wither Skeleton、Zombified Piglin、Spider、Cave Spider、Pillager、Vindicatorです。`config.yml` の `allowed-mobs` で変更できます。

初期設定では、Creeper、Enderman、Witch、Ghast、Blaze、Wither、Ender Dragon、Wardenなどは対象外です。設定で追加するMobは、Spigot APIから通常のMobとして扱える種類だけが有効です。

## データ保存

護衛EntityにはPersistentDataContainerでBodyGuard識別情報、所有者UUID、護衛UUID、種類、モード、名前、名前番号、お気に入り状態を保存します。`guards.yml` には管理情報、名前番号、待機・警備地点、解除予約、お気に入り状態を保存します。所有者ごとの相棒UUIDとチュートリアル状態は `players.yml` に保存します。位置にはワールド名とワールドUUIDを保存し、UUIDを優先して読み込みます。Entityが未読み込みの間は、表示で取得できないHP・距離を推測しません。

`guards.yml` の保存versionは3です。version 2以前にはお気に入り値がないため、自動的に未登録として読み込みます。既存の護衛、名前、モード、位置、解除予約はそのまま読み込みます。

`guards.yml` は変更がある場合に標準60秒間隔で自動保存します。保存時は一時ファイルを作成してから置き換え、直前の内容を `guards.yml.bak` に残します。プラグイン終了時には現在の内容を最終保存します。全解除はサーバー停止を避けるため未読み込みチャンクを強制ロードせず、未読み込み分を解除予約にします。

メニュー専用アイテムは1人1個までです。ドロップ、死亡時のドロップ、クラフト材料としての利用、通常コンテナ・作業台・金床・鍛冶台への移動を防止します。既存の `config.yml` は自動上書きされないため、以前の `NETHER_STAR` を `COMPASS` に変えたい場合は、サーバー停止中に `menu-opener.material` を手動で変更してください。

## ビルドとJarの入れ替え（ユーザーが実行）

この手順はサーバー管理者がコマンドプロンプトで実行してください。私は今回、Mavenビルド、テスト、サーバー起動を実行していません。

1. サーバーを停止します。
2. コマンドプロンプトを開きます。PowerShellではなく、次のようにプロジェクトへ移動します。

```bat
cd /d C:\Users\USER\Documents\Plugin\BodyGuard
build.bat
```

3. `Build completed successfully.` と表示されたら `target\BodyGuard.jar` を確認します。
4. サーバーの `plugins` フォルダにある古いBodyGuardのJarをバックアップしてから、新しいJarと入れ替えます。
5. サーバーを起動し、コンソールにエラーがないことを確認します。

`mvn clean package` を直接実行することもできます。Mavenが見つからない場合は、Mavenをインストールして新しいコマンドプロンプトを開くか、`MAVEN_HOME` を設定してください。既存の `config.yml`、`messages.yml`、`guards.yml` はバックアップしてから更新してください。作業前の `target/BodyGuard.jar` は、今回の変更が反映された完成品とは扱わないでください。

## 初心者向け手動確認手順

### 用意するもの

- 検証用のSpigot 1.21.8サーバーとJava 21
- OP、または確認したい権限を持つテストプレイヤー
- 同じ種類の対応Mobを2体以上召喚できる設定
- 護衛を一時的に傷つけるための敵Mobや安全な確認場所
- 名前変更、権限不足、未読み込みを確認するためのテスト用プレイヤーまたは別ワールド

ビルド、Jarの入れ替え、サーバー起動後に、次の順で「操作」と「成功の見え方」を確認してください。

1. **護衛0体から案内を押して召喚する** — `/bg` を開き、中央の「最初の護衛を召喚」をクリックします。召喚画面が開き、候補をクリックすると一覧に1体表示されれば成功です。
2. **召喚候補の特徴説明を確認する** — 召喚画面で候補にカーソルを合わせます。「攻撃タイプ」「特徴」と、権限・設定・上限の理由が説明欄に表示されれば成功です。
3. **同じ種類を2体召喚して名前で区別する** — 同じMobを2回召喚します。「ゾンビ護衛 01」「ゾンビ護衛 02」のように名前が異なれば成功です。
4. **GUIから名前を変更し、1体だけ変わることを確認する** — 1体の詳細で「名前変更」、金床入力、結果スロットの順に操作します。詳細へ戻った対象だけ名前が変わり、もう1体が変わらなければ成功です。
5. **名前変更をキャンセルする** — 詳細で「名前変更」を開き、文字を変えずに画面を閉じます。元の名前が維持されれば成功です。確定は必ず結果スロットのクリックです。
6. **しゃがみ＋右クリックで対象の詳細を開く** — メイン・オフハンドを空にして自分の護衛を見ながらしゃがみ、右クリックします。その護衛の詳細だけが開けば成功です。通常Mobや他人の護衛では通常操作が残ります。
7. **1体だけ回復する** — 2体のうち1体だけを傷つけ、その詳細で「この護衛を回復」をクリックします。対象のHPだけが最大になり、結果欄に対象名が出れば成功です。
8. **1体だけ呼び戻す** — 2体のうち1体を離れた安全な場所へ置き、詳細で「この護衛を呼ぶ」をクリックします。対象だけが戻り、他の護衛が移動しなければ成功です。
9. **負傷数などの概要表示を確認する** — 1体を傷つけ、一覧を手動更新します。「負傷中」が1体になり、HP不明の護衛は健康・負傷に推測で加算されなければ成功です。
10. **絞り込みと並べ替えを使う** — 一覧上部の「絞り込み」「並べ替え」をクリックして各条件を切り替えます。ボタン名が現在の条件を示し、近い順・HP割合順で不明値が末尾になれば成功です。
11. **詳細から戻って表示条件が維持されることを確認する** — 絞り込み、並べ替え、2ページ目を設定して護衛詳細を開き、「一覧に戻る」をクリックします。条件とページが維持されれば成功です。
12. **HP・距離の自動更新と位置固定を確認する** — 詳細または一覧を開いたまま護衛を傷つけたり移動させたりします。約1秒ごとに表示だけが更新され、HP順・距離順でもアイコンが勝手に別護衛へ入れ替わらなければ成功です。
13. **護衛へ照準を合わせる** — GUIを閉じ、自分の護衛を壁のない場所で見ます。画面下部に名前、モード、HPが表示され、視線を外すと消えれば成功です。
14. **選択中のモードアイコンを確認する** — 詳細で追従、待機、警備を選びます。選択中もリード、金床、盾のままで、「選択中」が文字で分かれば成功です。
15. **操作結果と音を確認する** — モード変更、単体回復、失敗する操作を行います。結果欄が数秒表示され、成功音と失敗音が本人だけに控えめに聞こえれば成功です。
16. **単体解除・全解除のキャンセルと確定を確認する** — 詳細の単体解除はキャンセルで同じ詳細へ戻り、管理画面の全解除はキャンセルで管理へ戻ることを確認します。その後に確定し、「解除済み・解除予約・失敗」の件数と通常Mobへ戻る注意が表示されれば成功です。遠方の解除予約は、対象チャンクへ近づいた時点で通常Mobへ戻ることも確認します。
17. **権限不足や未読み込みの説明を確認する** — テスト権限から `bodyguard.heal` などを外し、ボタンを押します。権限不足が文章で表示されます。未読み込みの護衛では「状態を確認できない」「手動更新」など次の行動が表示されれば成功です。
18. **GUI操作中に対象が死亡・解除された場合を確認する** — 詳細または一覧を開いたまま、別操作で対象を死亡・解除します。次の自動更新で無効表示になり、クリック時に別の護衛へ置き換わらなければ成功です。
19. **ログアウト・再ログイン後の状態を確認する** — GUIを開いたままログアウトし、再ログインします。古い入力画面、結果表示、アクションバーが残らず、再度 `/bg` を開ければ成功です。
20. **既存コマンドとGUIアイテム持ち出し防止を確認する** — `/bg help`、`/bg list`、`/bg summon zombie`、`/bg mode follow`、`/bg heal`、`/bg releaseall confirm` を実行します。既存コマンドが使え、GUIでShiftクリック、数字キー、ダブルクリック、ドラッグ、オフハンド交換をしてもアイテムを持ち出せなければ成功です。
21. **新しいキーがない既存設定を確認する** — 検証用コピーの `config.yml` と `messages.yml` から今回の新しいキーを一時的に外して起動します。GUIの日本語、更新間隔の既定値、特徴の汎用説明が表示され、操作できれば成功です。確認後は設定ファイルを戻してください。

上記は手動確認の手順です。今回の実装では、テスト、Mavenビルド、Minecraft/Spigotサーバー起動、ゲーム内確認を実施していません。

## Spigot APIだけでの実装

NMS、CraftBukkit内部クラス、Paper専用APIは使用していません。Mobの通常AIを基本的に残し、既存のターゲット制御・所有者判定・味方判定を使っています。そのため、Skeletonの弓やPillagerのクロスボウなど、元Mobの通常動作や装備条件を維持します。特殊AIや他プラグインによる変更まで完全に保証するものではありません。

## 既知の制約

- 単体の回復・呼び戻しは、未読み込みEntityをこの操作のために強制読み込みしません。護衛のいる場所で状態を確認してから手動更新してください。
- アクションバー表示と他プラグインの表示の完全な共存は保証しません。設定で無効化できます。
- 既存の `default-name` を使っているサーバーでは、互換性のためテンプレートを無断で変更しません。番号を表示したい場合は `{number}` をテンプレートへ追加してください。
- Mob本来のAIや他プラグインの干渉によって、追従・攻撃の見え方が変わる場合があります。
